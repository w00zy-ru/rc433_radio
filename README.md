# RC433 Radio — Приёмник RCSwitch-совместимых датчиков (ESP32 / ESP-IDF)

Компонент для приёма и декодирования данных от беспроводных датчиков, передающих данные на частоте 433 МГц по протоколу, совместимому с библиотекой [RCSwitch](https://github.com/sui77/rc-switch) (версия 2.6.4).

Использует аппаратные прерывания GPIO, IRAM-оптимизированный парсер таймингов, CRC8-валидацию пакетов и FreeRTOS-очереди для передачи данных в приложение.

## 🏗️ Архитектура

```
[Датчик 433МГц] ──> [GPIO ISR] ──> [rxTimings[]] ──> [rxDetectProtocol()]
                                                        │
                                                  [Ring Buffer]
                                                        │
                                            [vRadioFilterTask]
                                                  │
                                    ┌─────────────┼──────────────┐
                                    │             │              │
                              [CRC8 Check]  [Dedup Filter]   [Queue Send]
                                    │             │              │
                                    └─────────────┴──────────────┘
                                                        │
                                              [output_queue] ──> [app_radio.c]
                                                                 │
                                                          [decode packet]
                                                          [temp, volt, id]
```

### Потоки данных

1. **ISR (IRAM)** — `rxIsrHandler()` фиксирует длительности импульсов в `rxTimings[]` по каждому фронту/спаду GPIO.
2. **Протокольный детектор** — при разделительной паузе (> 4300 мкс) вызывается `rxDetectProtocol()`, который сопоставляет тайминги с активным протоколом (`RC433_TARGET_PROTOCOL`).
3. **Кольцевой буфер** — распознанный 32-битный пакет отправляется через `xRingbufferSendFromISR()` в промежуточный буфер.
4. **Filter Task (приоритет configMAX_PRIORITIES-2)** — извлекает пакеты, проверяет CRC8, фильтрует дубликаты (300 мс окно, история 4 записей), отправляет чистые данные в очередь приложения.
5. **Задача уровня приложения** — деконструирует 32-битный пакет.

## 🔧 Настройка протокола

Активный протокол задаётся макросом `RC433_TARGET_PROTOCOL` в `rc433_protocol.h` (значения 1–12). По умолчанию — **протокол 1** (pulseLength=350, sync=1:31, zero=1:3, one=3:1, non-inverted).

| Протокол | pulseLength | sync   | zero | one  | inverted |
|----------|-------------|--------|------|------|----------|
| 1        | 350         | 1:31   | 1:3  | 3:1  | no       |
| 2        | 650         | 1:10   | 1:2  | 2:1  | no       |
| 3        | 100         | 30:71  | 4:11 | 9:6  | no       |
| 4        | 380         | 1:6    | 1:3  | 3:1  | no       |
| 5        | 500         | 6:14   | 1:2  | 2:1  | no       |
| 6        | 450         | 23:1   | 1:2  | 2:1  | yes      |
| 7        | 150         | 2:62   | 1:6  | 6:1  | no       |
| 8        | 200         | 3:130  | 7:16 | 3:16 | no       |
| 9        | 200         | 130:7  | 16:7 | 16:3 | yes      |
| 10       | 365         | 18:1   | 3:1  | 1:3  | yes      |
| 11       | 270         | 36:1   | 1:2  | 2:1  | yes      |
| 12       | 320         | 36:1   | 1:2  | 2:1  | yes      |

> **Важно:** Для смены протокола измените `RC433_TARGET_PROTOCOL` и пересоберите проект.

## 📐 Структура пакета (32 бита)

```
┌──────────┬────────────┐
│ Биты 31-24 │ Биты 23-0| 
│ CRC8       │ Payload  |
│ (8 бит)    │ (24 бит) │
└──────────┴────────────┘
```

### Пример деконструкции в бизнес-логике:

| Поле       | Биты     | Формула                                   |
|------------|----------|-------------------------------------------|
| `id`       | 18–23    | `(packet >> 18) & 0x3F`                   |
| `volt`     | 11–17    | `((encoded_vbat * 20.0 + 2000.0) / 1000.0)` V |
| `temp`     | 0–10     | `((encoded_temp - 500) / 10.0)` °C        |
| `CRC8`     | 24–31    | Полином 0x07 по байтам 0–2 payload        |

## 🚀 Использование

### 1. Инициализация приёмника

```c
#include "rc433_receiver.h"

// Создаём очередь заранее
#define RX_QUEUE_LENGTH 4
QueueHandle_t rc433Queue = xQueueCreate(RX_QUEUE_LENGTH, sizeof(rx433_data_t));

// Конфигурация
rc433_config_t radio_config = {
    .output_queue = rc433Queue,
    .gpio_num     = GPIO_NUM_4,   // GPIO приёмника 433МГц
    .pull_up      = GPIO_PULLUP_DISABLE,
    .pull_down    = GPIO_PULLDOWN_DISABLE,
    .inverted_logic = false       // true для инвертированных приёмников (e.g. RBR-MS-A)
};

esp_err_t err = rc433_receiver_init(&radio_config);
```

### 2. Приём данных в задаче приложения

```c
void radio_task(void *arg) {
    rx433_data_t data;
    QueueHandle_t input_queue = (QueueHandle_t)arg;

    for (;;) {
        if (xQueueReceive(input_queue, &data, portMAX_DELAY) == pdTRUE) {
            // data.value — валидный 32-битный пакет с проверенным CRC
            // data.protocol — номер протокола
            // data.source — IDS_RX433
        }
    }
}
```

## 🔒 Потокобезопасность

- **ISR → Ring Buffer**: `xRingbufferSendFromISR()` — безопасная отправка из прерывания.
- **Filter Task → Output Queue**: `xQueueSend(..., 0)` — неблокирующая отправка (при переполнении пакет теряется с предупреждением в лог).


---

## 🛡️ Обработка ошибок

| Ситуация | Поведение |
|----------|-----------|
| Ошибка CRC8 | Пакет отбрасывается, предупреждение в лог (`ESP_LOGW`) |
| Переполнение очереди | Пакет теряется, предупреждение в лог |

## 🔬 Примечания по разработке

- Все массивы таймингов и критические переменные помечены `DRAM_ATTR` / `IRAM_ATTR` для работы в ISR.
- Задача фильтрации привязана к `tskNO_AFFINITY` (любое ядро) с приоритетом `configMAX_PRIORITIES - 2`.
- Стек задачи фильтрации: 3072 байт. Стек задачи приложения: 2048 слов.
- Для отладки таймингов подключите логический анализатор к GPIO и сравните с таблицей протоколов.
